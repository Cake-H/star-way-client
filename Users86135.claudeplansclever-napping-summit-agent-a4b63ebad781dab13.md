### Option A (Recommended): Use @vite-pwa/assets-generator

### Option B: Rasterize Existing favicon.svg with sharp

If you want to reuse the existing favicon directly, add a local script scripts/generate-icons.mjs:

```js
import sharp from "sharp"
import { readFileSync } from "node:fs"

const svg = readFileSync("./public/favicon.svg")
await Promise.all([
  sharp(svg).resize(192, 192).png().toFile("./public/pwa-192x192.png"),

])
console.log("Icons generated")
```

Then run:

```bash
pnpm add -D sharp
node scripts/generate-icons.mjs
```

> Warning: SVG filters in the current favicon may not render identically when rasterized by sharp. Visually verify both PNGs after generation.

- public/apple-touch-icon.png (180x180)

## Step 6: Graceful Service-Worker Update Handling

Create src/composables/usePWA.ts:

```ts
import { ref } from "vue"
import { useRegisterSW } from "virtual:pwa-register/vue"

export function usePWA() {
  const offlineReady = ref(false)
  const needRefresh = ref(false)

  const { updateServiceWorker } = useRegisterSW({
    immediate: true,
    onRegistered(r) {
      if (r) {
        // Periodically check for updates every hour
        setInterval(() => {
          r.update().catch(() => {})
        }, 60 * 60 * 1000)
      }
    },
    onOfflineReady() {
      offlineReady.value = true
    },
    onNeedRefresh() {
      needRefresh.value = true
    },
  })

  async function acceptUpdate() {
    await updateServiceWorker(true)
  }

  function dismissUpdate() {
    needRefresh.value = false
  }

  return {
    offlineReady,
    needRefresh,
    acceptUpdate,
    dismissUpdate,
  }
}
```

Then wire it into src/layouts/MainLayout.vue (or App.vue) to show an update prompt.

Add near the top of the template in MainLayout.vue:

```html
<el-alert
  v-if="needRefresh"
  :closable="false"
  type="success"
  show-icon
  class="pwa-update-toast"
>
  <template #title>
    <span>发现新版本，是否立即更新？</span>
    <el-button type="primary" size="small" @click="acceptUpdate">立即更新</el-button>
    <el-button size="small" text @click="dismissUpdate">稍后</el-button>
  </template>
</el-alert>
```

Add to the script setup block:

```ts
import { usePWA } from "@/composables/usePWA"

const { needRefresh, acceptUpdate, dismissUpdate } = usePWA()
```

Add scoped style:

```css
.pwa-update-toast {
  position: fixed;
  top: 16px;
  left: 50%;
  transform: translateX(-50%);
  z-index: 2000;
  min-width: 320px;
}
```

### Why registerType: "prompt" + manual update?

- Default autoUpdate forcibly reloads the page when a new SW is waiting, which can interrupt a user session.
- prompt lets the app show a toast; the user chooses when to activate the new version.

## Trade-offs and Gotchas

1. **Icon quality from SVG filters**: the existing favicon.svg uses SVG filters/blur. Rasterizers may produce slightly different output. A simplified source icon is safer for crisp 192/512 PNGs.
2. **Service worker caching during dev**: enabling devOptions.enabled: true can cause stale assets while developing. Keep it disabled unless testing PWA-specific behavior.
3. **Update prompt UX**: with registerType: "prompt", users may never refresh. Balance by periodically calling r.update() and showing a non-blocking toast.
4. **API calls and offline**: all /api calls are excluded from the navigate fallback, but they are not cached by default. Add runtimeCaching rules if offline API resilience is needed.
5. **Base URL / deployment path**: if the app is deployed under a subpath, set base in vite.config.ts and ensure scope/start_url match.
6. **Authentication flow**: the app redirects unauthenticated users to /login. The service worker must serve index.html for all navigations so the router can handle redirects; this is covered by navigateFallback: "index.html".
7. **Cache invalidation**: workbox precaches hashed filenames, so normal deployments invalidate correctly. For API/runtime data, implement explicit caching rules.
8. **Element Plus size**: workbox precaches all JS chunks; the initial install may be large. Consider code-splitting or lazy-loading large components if install size becomes an issue.
